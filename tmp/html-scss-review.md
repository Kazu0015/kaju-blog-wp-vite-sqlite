# HTML / SCSS レビュー依頼プロンプト

以下の HTML と SCSS を、フロントエンドのコードレビュー担当としてレビューしてください。

レビューでは、特に以下の観点を重視してください。

## コンテキスト情報

レビューの前提として、以下の情報も考慮してください。
未記入の項目がある場合は、分かる範囲で前提を置いてレビューし、不明点として明記してください。

- ページの種類・目的: （例: ブログ記事ページ / コーポレートサイトのトップページ / LP / お問い合わせページ）
- 公開状態: （例: 本番公開予定 / 学習用 / ローカル検証用）
- ターゲットブラウザ: （例: モダンブラウザのみ / Safari含む / IE11対応が必要）
- BEM の流儀: （例: 厳格なBEM / MindBEMding準拠 / プロジェクト独自ルールあり）
- デザインカンプの有無: あり / なし
- 既存のSCSS変数・mixin定義ファイルの有無: あり（別途共有） / なし
- 特に重点的に見てほしい観点: （例: アクセシビリティ / BEM / headタグ / レスポンシブ）

## レビュー優先順位

指摘が多い場合は、以下の優先順位を目安に、重要度の高いものから並べてください。

1. アクセシビリティ・セマンティクス
2. BEM / CSS設計・SCSS品質
3. headタグ・メタ情報・SEO
4. レスポンシブ・表示品質
5. その他の改善点

## レビュー観点

### 1. セマンティクス

- HTMLタグの選択が適切か
- 見出し構造が自然か
- `section` / `article` / `nav` / `main` / `aside` / `footer` などが適切に使われているか
- `div` や `span` の使いすぎがないか
- 文書構造として、内容の意味が正しく伝わるか

### 2. アクセシビリティ

- `alt` 属性、`aria` 属性、`label` が適切に使われているか
- `button` と `a` の使い分けが適切か
- キーボード操作に問題がないか
- フォーカス状態が視覚的に分かるか
- スクリーンリーダーで意味が伝わる構造か
- 色だけに依存した表現がないか
- コントラストや文字サイズに懸念がないか
- 可能であれば WCAG 2.2 の AA 準拠を目安に問題点を指摘すること

### 3. BEM / CSS設計

- クラス名が BEM の命名規則に沿っているか
- Block / Element / Modifier の分け方が自然か
- Modifier が状態やバリエーションを適切に表しているか
- ネストが深すぎないか
- 再利用しにくいスタイルになっていないか
- 詳細度が高すぎるセレクタがないか
- 命名に一貫性があるか

### 4. SCSS品質

- 変数、mixin、関数の使い方が適切か
- 色、余白、フォントサイズなどを変数化できる箇所がないか
- 重複しているスタイルがないか
- レスポンシブ対応が保守しやすいか
- マジックナンバーが多すぎないか
- 不要なスタイルや効いていないスタイルがないか
- ブラウザ互換性に懸念がないか
- `@use` / `@forward` が適切に使われているか
- 非推奨の `@import` に依存していないか
- ファイル分割やディレクトリ構成に問題がないか
- `variables` / `mixins` / `base` / `components` / `layout` などの責務分離が自然か

### 5. 保守性・可読性

- HTML と SCSS の対応関係が分かりやすいか
- 将来的な変更に強い構造か
- 命名が見た目ではなく役割や意味を表しているか
- コンポーネント単位で分割しやすいか
- 他のページやパーツでも再利用しやすいか

### 6. SEO

- `h1` が適切に使われているか
- 見出し階層が検索エンジンにも理解しやすいか
- 画像の代替テキストが内容に合っているか
- 本文構造が自然で、重要な情報が HTML 上で読み取れるか
- 必要に応じて構造化データやメタ情報の改善余地があるか

### 7. headタグ・メタ情報

- `title` がページ内容を適切に表しているか
- `meta name="description"` が設定され、ページ内容に合っているか
- `meta charset` が適切に設定されているか
- `meta name="viewport"` が適切に設定されているか
- canonical URL が必要なページで設定されているか
- OGP 関連の `og:title` / `og:description` / `og:type` / `og:url` / `og:image` が適切に設定されているか
- `og:image` のパス、画像サイズ、内容が適切か
- `og:image` がない場合は、作成を促し、推奨される解像度、形式、ファイルサイズ、内容の方向性を具体的に提示すること
- Twitter Card 関連の `twitter:card` / `twitter:title` / `twitter:description` / `twitter:image` が必要に応じて設定されているか
- favicon や apple-touch-icon が必要に応じて設定されているか
- 不要、重複、または矛盾した `meta` タグがないか
- CSS、フォント、外部リソースの読み込み順に問題がないか
- ページ表示やSEOに不要な外部リソースを読み込んでいないか

### 8. レスポンシブ・表示品質

- モバイル、タブレット、デスクトップで崩れにくい設計か
- 固定幅に依存しすぎていないか
- 文字やボタンが小さすぎないか
- コンテンツの折り返しや余白が自然か
- レイアウトシフトや重なりが起きそうな箇所がないか

### 9. その他の改善点

- パフォーマンス上の懸念
- 不要コードや未使用クラス
- 画像、アイコン、装飾要素の扱い
- より自然な実装方法
- 実務上、レビューで指摘されそうな点

## 出力形式

以下の形式でレビューしてください。

### 総評

コード全体の印象を簡潔に述べてください。

### 重要度の高い指摘

致命的、または優先度の高い問題を箇条書きで指摘してください。
指摘ごとに、重要度を `[高]` `[中]` `[低]` のいずれかで示してください。

### 観点別レビュー

以下の観点ごとにレビューしてください。

- セマンティクス
- アクセシビリティ
- BEM / CSS設計
- SCSS品質
- 保守性・可読性
- SEO
- headタグ・メタ情報
- レスポンシブ・表示品質
- その他

### 修正例

重要度の高い指摘に絞って、修正前・修正後のコード例を示してください。
軽微な指摘は、理由と修正方針の説明だけで構いません。

`og:image` が未設定の場合は、以下のような具体的な作成ガイドも提示してください。

- 推奨解像度: `1200 x 630px`
- 推奨比率: `1.91:1`
- 推奨形式: `jpg` または `png`
- 推奨ファイルサイズ: できれば `300KB` 程度まで、重くても `1MB` 未満を目安
- 内容: ページタイトル、サイト名、ページ内容が伝わる画像やキービジュアル
- 注意点: 端が切れても意味が伝わるよう、重要な文字やロゴは中央寄せ気味に配置する
- 実装例: `<meta property="og:image" content="https://example.com/path/to/ogp.jpg">`

### 良い点

良くできている点を最低3つ挙げてください。
それぞれ、なぜ良いのか理由も添えてください。

### 最終チェックリスト

今回のコードで実際に見つかった問題・惜しかった点をもとに、次回から自分で確認できるチェックリストを作ってください。
汎用的な一般論ではなく、今回の指摘に紐づいたリストにしてください。

## レビューの姿勢

遠慮せず、実務のコードレビューとして厳しめに指摘してください。
ただし、指摘には必ず理由と改善案を添えてください。
指摘が多い場合は、重要度順に並べ、軽微なものは簡潔にまとめてください。

私はフロントエンド学習中です。
単に修正案を出すだけでなく、なぜその修正が必要なのかも分かるように説明してください。
